# ELIGIBILITY.md — permission declaration vs authorization eligibility (v1.5, FROZEN_NOW as law; evaluator is a reference, not runtime-qualified)

**Permission declaration** (`PERMISSIONS.json`, `allowed: true`): what an operation is theoretically permitted to do under a milestone and scope. **Authorization eligibility**: whether *this* request, the frozen authorities, the **active reviewed authority** and the linked evidence set currently satisfy every prerequisite. `allowed: true` never makes a request eligible.

## v1.5 law: the evaluator consumes validated, envelope-bound, current evidence — never caller assertions

Reference evaluator: `authority_lib.evaluate_eligibility(perms, request, read_primitives, capabilities, target_contract, evidence_set, active)`.

`active` = `{authority_version, manifest_sha256, capability_matrix_sha256}` of the reviewed authority the evaluator runs under (this bundle: `1.5.0`, the sha256 of its `FREEZE-MANIFEST.json`, the sha256 of its `CAPABILITIES.json`). It is an input of the deployment, not of the request. Every evidence record must be envelope-bound to it (`TARGET-ATTACHMENT-GATE.md`); a set containing a record bound to another manifest or authority version is invalid and the derived state is `CONFLICT`.

Inputs are the frozen authorities (`PERMISSIONS.json`, `READ-PRIMITIVES.json`, `CAPABILITIES.json`, `TARGET-CONTRACT.json`), the active authority, a **validated evidence set** (`schemas/resolveEvidenceSet.schema.json`: `current_session_id`, `evaluated_at`, content-addressed envelope-bound records) and a **request** (`schemas/resolveEligibilityRequest.schema.json`): `milestone`, `operation`, `scope`, `expected_project_name?`, `expected_timeline_name?`, `transaction_id?`, `plan_digest?`, `plan_h0_guard_digest?`, `refs` (sha256 references by role: `authorization`, `journal_prepared`, `read_only_journal`, `guard`, `plan_validation`, `m0_exit`, `m1_exit`, `m2_exit`, `exclusive_session`, `media_class`, `destination_timeline`).

The request schema has `additionalProperties: false`: `attachment_state`, `capability_state`, `evidence`, `journal_available`, `guard_available`, `authorization_token` are **not request fields** (retired). The evaluator never reads them; fixtures `m0-probe-deny-declared-state-ignored` and `m0-connect-deny-qualified-read-string-ignored` prove a request carrying them is both schema-invalid and still denied.

Derived, not declared:
- **Attachment state** — `derive_attachment_state(target_contract, evidence_set, active)` (`TARGET-ATTACHMENT-GATE.md`). `TARGET_STATE_*` codes compare the derived state; `CONFLICT` short-circuits the whole evaluation with reason `ATTACHMENT_CONFLICT` and the conflict list; nothing is eligible.
- **Primitive qualification** — `primitive_status(capabilities, primitive, method, evidence_set, env, active)`: `QUALIFIED_CALLABLE` only when the **active** matrix row is `QUALIFIED_READ` under a reviewed `refreeze` block whose `promoted_probe_ids` **and** `promoted_evidence_sha256` name the exact evidence, the row's evidence-record entry cites `(method, probe_id, raw_evidence_sha256, result SUCCESS)`, and a linked `CAPABILITY_EVIDENCE` record passes `capability_record_qualifies` → `capability_success` (v1.5, the one canonical predicate: raw evidence present, re-hashing and from the same session; parse succeeded with no error and no getter exception; `receiver_type` and `observed_type` equal the primitive's `receiver`/`expected_type`; shape ok and non-null; label SUCCESS **and** derived classification SUCCESS; exact host/product/version/build; `reviewed: true` + `ACCEPT` with `review_raw_evidence_sha256` equal to this record's raw hash; `promoted_by` naming the active authority version, the active matrix sha **and** this raw hash). `PROBE_ALLOWED` only inside `READ_PRIMITIVE_QUALIFICATION_PROBE` for `probe_candidate` rows. Otherwise `UNQUALIFIED` and the declared fallback decides (`REFUSE` blocks). A label, a review or a refreeze never overrides a parsed failure (`M0-PROBE-CONTRACT.md`).
- **Evidence references** — `resolve_ref(evidence_set, ref, expected_type, envelope, extra, active)`: a reference is evidence only if it is a lowercase 64-hex sha256, exists in the set, has the expected `record_type`, re-hashes to its id, is bound to the active manifest and authority version, and matches the required envelope fields (host; for session-scoped roles the current `session_id`; for project/timeline-scoped roles the expected names) and extra fields (`plan_digest`, `transaction_id`, `milestone`, `authority_version`, `scope`, `library_name`, `result`). `""`, `"false"`, uppercase, short, unlinked, wrong-type, other-manifest or other-host references fail (fixtures `m0-deny-ref-*`, validator `evidence-ref-negative`). `GUARD_CURRENT` additionally requires the referenced `GUARD_SNAPSHOT` to be the **current** guard observation of the session for that project/timeline (a newer guard record makes the plan stale: fixture `plan-guard-record-not-current`).
- **Target requirement** — every permission entry and logical read operation declares `target_requirement ∈ {SESSION, PROJECT, PROJECT_TIMELINE}` (must agree; `semantic_read_primitives`). `SESSION`: host/session/library boundary only (`READ_PRIMITIVE_QUALIFICATION_PROBE`, `CONNECT`, `ENUMERATE_PROJECTS`, `CreateProject`); no project or timeline record is required or consulted (fixture `m0-enumerate-projects-allow-without-any-binding-records`). `PROJECT`: `expected_project_name` proven by the **current** `PROJECT_BINDING_OBSERVATION` of the current session for that name, whose envelope cites the contract library and the provisioning record; the name must be adapter-prefixed or covered by an `OPERATOR_PROVISIONED_PROJECT` record for the contract library (`ENUMERATE_TIMELINES`, `TRIPWIRE_READ`, `LoadProject_adapterPrefixed`, `CreateEmptyTimeline`, `SaveProject`, `ImportMedia`). `PROJECT_TIMELINE`: additionally `expected_timeline_name` proven by the current `TIMELINE_BINDING_OBSERVATION` bound to the same library, provisioning record, project (name and id) and timeline (`SNAPSHOT_CAPTURE`, `TIMEBASE_OBSERVE`, `SetCurrentTimeline`, `BUILD_MUTATION_PLAN_DRY_RUN`, every M3 timeline mutation). Mutation-capable entries additionally require `OBSERVED` project/timeline unique ids. Bindings from another session, another library or another provisioning record never bind (fixtures `m0-snapshot-deny-binding-from-other-session`, `m0-snapshot-deny-cross-library-timeline-binding`). **No operation ever binds to whatever project or timeline is current.** The evaluator enforces the binding even if an entry omitted `TARGET_REQUIREMENT_SATISFIED`.

Output: `permitted_by_policy`, `prerequisites_satisfied`, `eligible`, `failed_prerequisites[]` (code + reason), `reason_codes[]`, `derived_attachment_state`, `attachment_conflicts[]`, `target_requirement`, `expanded_primitives[]` (method, status, callable, fallback). Unknown milestone/scope/operation/prerequisite, invalid or unbound evidence set, `CONFLICT`, missing binding or unlinked reference fails closed. The result is a pure function of its inputs: the validator re-evaluates every case under seeded permutations of the evidence map and request key order and requires identical output.

## Prerequisite codes (closed set, `PERMISSIONS.json.prerequisite_codes`, 23; unchanged names, v1.4 semantics)

`BUNDLE_INDEPENDENTLY_VERIFIED` (derived proof: `BUNDLE_VERIFICATION` bound to the active manifest + `1.5.0` on the contract host, verifier ≠ preparer, not historical), `TARGET_STATE_ATTACHMENT_READY` / `TARGET_STATE_ATTACHED_READ_ONLY` / `TARGET_STATE_SCRATCH_WRITE_READY` (derived state rank; `CONFLICT` fails all), `HOST_MATCHES_CONTRACT` (valid provisioning record for contract host/library), `LIBRARY_NOT_SHARED`, `LIBRARY_MATCHES_CONTRACT` (no `OBSERVED_TARGET_MISMATCH`), `RESOLVE_VERSION_MATCHES` (current connection observation proof), `M0_EXIT_EVIDENCE` / `M1_EXIT_EVIDENCE` / `M2_EXIT_EVIDENCE` (`MILESTONE_EXIT` bound to the active authority), `MIKKO_M3_AUTHORIZATION` (`M3_AUTHORIZATION` scope `SCRATCH_QUALIFICATION_LIBRARY`, approver, authority `1.5.0`, contract library), `JOURNAL_PREPARED` (current session, expected project, this `transaction_id` and `plan_digest`), `READ_ONLY_JOURNAL_OPEN` (current session), `GUARD_CURRENT` (current `GUARD_SNAPSHOT` of the session equal to the plan's `h0_guard_digest`), `EXCLUSIVE_SESSION_ATTESTED` (current session), `PROJECT_ADAPTER_PREFIXED`, `PRIMITIVES_QUALIFIED_OR_DECLARED_UNOBSERVED`, `PROBE_ALLOWED_PRIMITIVES` (probe only), `PLAN_VALIDATED` (`PLAN_VALIDATION` PASS for this `plan_digest` under `1.5.0`), `SYNTHETIC_MEDIA_ONLY`, `TIMELINE_IS_DESTINATION` (current session, expected names), `TARGET_REQUIREMENT_SATISFIED`.

## Consequences at v1.5

`CAPABILITIES.json` has zero `QUALIFIED_READ` rows and an unreviewed `refreeze` block, so `callable_method_set` is empty: `CONNECT` and `TIMEBASE_OBSERVE` (`REFUSE` fallbacks) are not eligible at any milestone; `READ_PRIMITIVE_QUALIFICATION_PROBE` is the first and only session-establishing M0 operation; `ENUMERATE_PROJECTS`, `ENUMERATE_TIMELINES`, `TRIPWIRE_READ` and `SNAPSHOT_CAPTURE` are eligible only in degraded mode once the derived state is `ATTACHED_READ_ONLY` and their bindings are current — and a degraded `SNAPSHOT_CAPTURE` may contain only what `SNAPSHOT-COMPLETENESS.md §Pre-qualification capture` allows. Qualification happens only through the pipeline in `M0-PROBE-CONTRACT.md`.
