# SEMANTIC-VALIDATION.md — schema validity is not authorization (v1.5, FROZEN_NOW as doctrine; validators NOT runtime-qualified)

**SCHEMA-VALID != AUTHORIZED TO MUTATE.** JSON Schema proves shape. Authority requires the layers below, implemented as a reference in `tools/authority_lib.py` and exercised by `tools/validate_v1_5.py`. Nothing has run against Resolve.

## Authority surface (v1.5)

`authority_lib.AUTHORITY_SURFACE` is the closed list of functions that may decide anything:
- **authorizing**: `commit_eligibility` (the ONLY commit entry point), `validate_transaction_set` (the composed transaction validator it wraps), `evaluate_eligibility`, `derive_attachment_state`, `primitive_status`, `callable_method_set`;
- **INTERNAL_NON_AUTHORIZING** (composed by the above; documented as such in every docstring; never an authorization surface): `semantic_mutation_plan`, `semantic_journal`, `semantic_verification_result`, `semantic_conflict`, `semantic_commit_manifest`, `semantic_snapshot`, `verify_transaction`, `derive_delta`, `occurrence_index`, `expected_effects`, `guard_lineage_errors`, `journal_readback`, `capability_success`, `capability_record_qualifies`, `semantic_capability_record`, `profile_satisfies`, `required_s1_profile`.

The v1.4 direct helpers survive only as these internal functions. `semantic_commit_manifest` and `semantic_verification_result` require plan, S0, S1, journal (and the active authority) as objects and return an error for any missing input — there is no hash-only path and no default that lets a caller omit S0 or S1. `validate_transaction_set` has no callable-set, skip or override parameter; it derives the capability/provenance context itself. The validator's `bypass-audit` section checks the surface list, the docstrings, the signatures and the behaviour of every exported validator.

## Layers (every fixture records its expected failure layer)

`raw parse` → `schema` → `evidence-binding` → `attachment` → `capability` (derived success pipeline) → `snapshot` (observation model, field provenance, occurrence uniqueness) → `semantic` (binding, membership, readback→S1, derived verification) → `eligibility` → `linked-set` / composed authorization. A positive fixture must pass every layer; a negative must fail at exactly the declared layer with the declared error substring. A check that raises is a **FAIL**. Seeded random permutations of evidence maps, request keys, snapshot arrays (tracks/items/markers/ledger), conflicts and linked-set key order must give identical results; duplicate-identity inputs must reject identically. The Codex v1.4 attacks and their combinations are pinned in `v1.4-attack`.

## Linked artifact identity (v1.5)

Bound across plan, journal (every record), S0, S1, verification and commit — no partial combination is accepted: **`authority_version`** (`1.5.0`), **`plan_digest`** (= `digest(plan without plan_digest/refs, vidtoolz.resolveMutationPlan.v1)`), **`transaction_id`**, **target** (`target` / `target_ref` / S0-S1 library+project+timeline identity + `target_epoch`), **H0/S0 guard** (`h0_guard_digest` = S0 `guard_digest` = journal `guard_digest` = commit `guard_digest`), **`operation_set_digest`** (plan, every journal record, commit; `expected_delta_digest` in verification), **execution/readback session** (`plan.session_id` = every journal record `session_id` = `S0.collection.session_id` = `S1.collection.session_id` = `verification.session_id` = `commit.session_id` = `evidence_set.current_session_id`), **S1 digest** (journal `READBACK_S1.readback_snapshot_sha256` = `verification.readback_snapshot_sha256` = `commit.s1_snapshot_sha256` = `snapshot_object_digest(S1)`; `readback_guard_digest` = `s1_guard_digest` = S1 `guard_digest`), **verification digest** (`commit.verification_result_sha256` = `digest(verification, vidtoolz.resolveVerificationResult.v1)` of the object that passed).

## Per-document rules

- **Plan** (`semantic_mutation_plan`): `plan_digest` and `operation_set_digest` recompute; unique operation ids; `session_id` present and equal to the evidence set's current session; permission class × ops; selector completeness and target match; `APPEND` requires `expected_new {start, end}`; guard presence; `STALE_SNAPSHOT` if the current guard differs; dry-run law; every operation eligible under the active authority.
- **Journal** (`semantic_journal(records, plan, s1)`): non-empty; single `transaction_id`, `plan_digest`, `operation_set_digest`, `session_id` (== plan), constant `target_ref`; constant `guard_digest` except across `RECOVERY_RECONCILING`; contiguous sequence; hash chain; execution law `PREPARED → LEASED → PREFLIGHT_OK → [CHECKPOINTED] → OP_STARTED → APPLIED | OP_FAILED → READBACK_S1 → VERIFIED → SAVED → PUBLISHED → COMMITTED` (+ failure/recovery branches); operation membership (op id + type from the bound plan; started/applied at most once; APPLIED after its own OP_STARTED; READBACK_S1 after every plan op APPLIED); **readback binding**: at most one `READBACK_S1`, carrying `readback_snapshot_sha256` and `readback_guard_digest`; only that record may carry them; when S1 is supplied they must equal `snapshot_object_digest(S1)` and S1's guard, S1 must be from the journal's session, and a supplied S1 without a readback event is an error.
- **S0 / S1** (`semantic_snapshot(snap, ctx)`, `guard_lineage_errors`): schema + semantic validity under the active authority context (callable set derived; every OBSERVED field/domain backed by cited qualifying provenance; unique occurrence identity); S0 is a complete `WRITE_PRECHECK` snapshot whose guard is the plan's H0 and whose identity equals the plan target; S1 shares library, project, timeline identity, `target_epoch` **and session** with S0 and the plan; S1 satisfies the operation's verify profile (`required_s1_profile`, `profile_satisfies`) and is complete.
- **Protected surface and derived delta** (`derive_delta`): occurrence index by OBSERVED `unique_id` (duplicates → `DUPLICATE_OCCURRENCE_IDENTITY`, not derivable); per occurrence `PROTECTED_ITEM_FIELDS` = track type/index, start, end, duration, enabled, media pool item id, media id, source start/end, source sha/locator/status, name, provenance kind, item markers; `PROTECTED_TIMELINE_FIELDS` = unique_id, name, start_frame, end_frame, start_timecode, fps, width, height, settings (`is_current` and `duration_convention` are explicitly unprotected — adapter selection state and a constant); `PROTECTED_TRACK_FIELDS` = name, enabled, locked plus track topology (tracks added/removed); timeline markers added/removed; media dependencies added/removed. Result: `added`, `removed`, `changed`, `markers_added/removed`, `timeline_changed`, `tracks_added/removed/changed`, `media_added/removed`.
- **Unrelated-change law** (`verify_transaction`): every protected change not explained by an APPLIED plan operation's expected effect is `unrelated`; `unrelated` and `missing_expected` are derived, never declared; a caller's `unrelated: []` is compared against the derived truth and rejected when it differs. Explained by APPEND: the new occurrence matching track/range/media identity (creation identity mapped), a media dependency for that occurrence's source, and `timeline.end_frame` growing exactly to the new occurrence end (or end+1 under the unqualified convention). Verdicts: `VERIFIED` | `EXPECTED_DELTA_MISSING` | `UNEXPECTED_DELTA` | `UNOBSERVABLE_STATE` (incomplete S0/S1, unobserved or duplicate identity) | `EFFECT_NOT_SPECIFIED`.
- **Expected effects** (`expected_effects`, provisional): APPEND → added item on selector track at `expected_new` with expected media identity; DELETE → removed; DISABLE/ENABLE → enabled flip only; UPSERT_MARKER → marker present by `custom_data`; every other op → NOT_YET_SPECIFIED (never VERIFIED).
- **Verification** (`semantic_verification_result(vr, plan, s0, s1, journal)` — all mandatory): declared `added/removed/changed/creation_identity_map/missing_expected/unrelated/verdict` equal the derived truth; `VERIFIED` requires every effect matched, every op APPLIED, no unrelated change, effects specified; `h0_*` digests resolve to S0 and `s1_*` + `readback_snapshot_sha256` to S1; readback digest equals the journal's single `READBACK_S1`; bound to plan/transaction/target/guard/expected-delta/session; never human approval.
- **Conflict** (`semantic_conflict`): `authority_effect NONE_UNTIL_HUMAN_ADJUDICATION`; bound to plan/transaction; `resolved` is a human flag.
- **Commit manifest** (`semantic_commit_manifest(cm, plan, journal, verification, conflicts, s0, s1, active)` — all mandatory): re-validates journal (with S1) and verification (against derived truth); same plan/transaction/target/guard/operation set/session; `s1_guard_digest` and `s1_snapshot_sha256` = S1; `journal_head_sha256` = chain head; `verification_result_sha256` = digest of the validated object; verdict VERIFIED; terminal state allowed; no unresolved conflict; evidence digests; authority version.

## Single authority: `commit_eligibility` → `validate_transaction_set`

`validate_transaction_set({s0_snapshot, plan, journal, s1_snapshot, verification, commit, conflicts}, perms, rp, caps, tc, evidence_set, active, schema_validate)` executes `VALIDATION_STAGES` in order and cannot skip any: **evidence_authority** (`validate_evidence_set` against the active manifest) → **capability_provenance** (context from the active matrix + evidence set) → **schema** (every member) → **s0** (semantic + provenance + complete `WRITE_PRECHECK`) → **plan** (against S0's guard, eligibility under the active authority) → **journal** (membership, session, readback binding to S1) → **s1** (semantic + provenance, lineage incl. session, required verify profile, completeness) → **delta** (identity errors) → **effects** (`verify_transaction`; a non-VERIFIED derived verdict with a commit present is an error) → **verification** (declared vs derived) → **conflicts** → **commit** (INELIGIBLE without linked S1 and verification). `commit_eligibility` requires S0, plan, journal, S1, verification and commit objects and returns `{eligible, errors, stages_completed}`; it is eligible only with zero errors and every stage completed. A verification object, a hash or a receipt is never sufficient on its own; missing linked S0/S1 → INELIGIBLE; a false VERIFIED object → INELIGIBLE.
