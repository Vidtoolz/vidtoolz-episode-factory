# SEMANTIC-VALIDATION.md — schema validity is not authorization (v1.4, FROZEN_NOW as doctrine; validators NOT runtime-qualified)

**SCHEMA-VALID != AUTHORIZED TO MUTATE.** JSON Schema proves shape. Authority requires the layers below, implemented as a reference in `tools/authority_lib.py` and exercised by `tools/validate_v1_4.py`. Nothing has run against Resolve.

## Layers (every fixture records its expected failure layer)

`raw parse` (strict duplicate-key rejection, `strict_loads`) → `schema` (Draft 2020-12) → `evidence-binding` (envelope law + active manifest binding, `validate_evidence_set`) → `attachment` (`derive_attachment_state`: coherence, currency, `CONFLICT`) → `capability` (`primitive_status` / `capability_record_qualifies`) → `snapshot` (`semantic_snapshot` with capability→coverage coupling) → `semantic` (reference rules per document: binding, membership, derived verification) → `eligibility` (`evaluate_eligibility`) → `linked-set` (`validate_transaction_set`). `layer_expected_failure ∈ FIXTURE_LAYERS`. A positive fixture must pass every layer; a negative must fail at exactly the declared layer with the declared error substring. A check that raises an exception is recorded as **FAIL**. The suite additionally re-runs eligibility, attachment, snapshot and linked-set checks under seeded random permutations (evidence map order, request key order, snapshot arrays, conflicts) and requires identical results, and asserts the v1.3 independent attacks fail at their intended layer (`v1.3-attack`).

## Cross-artifact binding tuple (v1.4)

Shared by mutation plan, transaction journal, verification result, conflict record and commit manifest: **`plan_digest`** (= `digest(plan without plan_digest/refs, vidtoolz.resolveMutationPlan.v1)`), **`transaction_id`**, **target identity** (`target` in plan/verification/commit; `target_ref` = library UUID + project id + timeline id in every journal record), **guard** (`h0_guard_digest` in plan/verification; `guard_digest` in every journal record and the commit; `s1_guard_digest` in verification and commit), **operation set** (`operation_set_digest` = `digest(operations, vidtoolz.resolveOperationSet.v1)` in plan, **every journal record** and commit; `expected_delta_digest` in verification), **`authority_version`** (`1.4.0`, const in the provisional schemas).

## Per-document rules

- **Plan** (`semantic_mutation_plan(plan, perms, rp, caps, tc, es, active, current_guard)`): `plan_digest` and `operation_set_digest` recompute; unique non-empty `operation_id`s; permission class × ops; selector completeness and target match; `APPEND` requires `expected_new {start, end}`; guard presence for guard-required ops; `STALE_SNAPSHOT` if the current guard differs; dry-run law; payload-as-guard rejected; every operation eligible via `evaluate_eligibility` with the plan's `refs` under the active authority (non-dry-run).
- **Journal** (`semantic_journal(records, plan)`): non-empty; single `transaction_id`, `plan_digest`, `operation_set_digest`, constant `target_ref`; constant `guard_digest` except across `RECOVERY_RECONCILING`; contiguous sequence from 0; hash chain over `vidtoolz.resolveJournalRecord.v1`; **execution law** `PREPARED → LEASED → PREFLIGHT_OK → [CHECKPOINTED] → OP_STARTED → APPLIED | OP_FAILED → READBACK_S1 → VERIFIED → SAVED → PUBLISHED → COMMITTED`, failure branch `OP_FAILED → ABORTED | RECOVERY_RECONCILING`, recovery `RECOVERY_RECONCILING → NOT_APPLIED | COMMITTED_RECOVERED | ORPHANED_*`; **operation membership**: `OP_STARTED`/`APPLIED`/`OP_FAILED` must name an `operation_id` of the bound plan with the same `op`; each op started at most once and applied at most once, `APPLIED` only after its own `OP_STARTED`; `READBACK_S1` only after every plan operation is `APPLIED`; non-operation records carry null `operation_id`/`op`; `RECOVERY_RECONCILING.recovery_of_transaction_id == transaction_id`; nothing after a terminal state. `journal_applied_ops` derives the applied set from the records.
- **S0 / S1** (`semantic_snapshot`, `guard_lineage_errors`): both snapshots must be schema-valid and semantically valid under the callable set of the active authority; S0 must be a complete `WRITE_PRECHECK` snapshot whose `guard_digest` is the plan's `h0_guard_digest` and whose identity equals the plan target; S1 must share library, project, timeline identity and `target_epoch` with S0.
- **Derived delta** (`derive_delta(s0, s1)`): by item `unique_id` (requires `OBSERVED` identity on every item, else not derivable → `UNOBSERVABLE_STATE`): `added`, `removed`, `changed` (track, start, end, enabled, media pool id, name before/after), `markers_added`, `markers_removed`. Caller-supplied lists are never truth.
- **Expected effects** (`expected_effects(plan)`, provisional): `APPEND` → `ADDED_ITEM` on the selector track at `expected_new.start/end` with `expected_media_pool_item_unique_id`; `DELETE` → `REMOVED_ITEM`; `DISABLE`/`ENABLE` → `ENABLED_FLAG` flip only; `UPSERT_MARKER` → `MARKER_PRESENT` by `custom_data`; every other op → `NOT_YET_SPECIFIED` (cannot verify; verdict `EFFECT_NOT_SPECIFIED`). Nothing beyond this is claimed about runtime semantics.
- **Verification** (`verify_transaction(plan, s0, s1, journal)` → derived truth; `semantic_verification_result(vr, plan, s0, s1, journal)`): the declared `added/removed/changed/creation_identity_map/missing_expected/unrelated/verdict` must equal the derived truth; `VERIFIED` requires every expected effect matched to a distinct delta entry (creation identity mapped for `APPEND`), every plan op `APPLIED` in the journal, no unrelated delta, effects specified for every op; `h0_*` digests resolve to S0, `s1_*` digests and `readback_snapshot_sha256` resolve to S1 (`snapshot_object_digest`); bound to plan/transaction/target/guard/expected-delta; never human approval. A syntactically valid hash is never sufficient.
- **Conflict** (`semantic_conflict(cf, plan)`): `authority_effect NONE_UNTIL_HUMAN_ADJUDICATION`; bound to `plan_digest`/`transaction_id`; `resolved` is a human flag.
- **Commit** (`semantic_commit_manifest(cm, plan, journal, verification, conflicts, s0, s1, active)`): **composes** validation — journal (membership) and verification (against derived truth) are re-validated here (a hash-only caller is refused); same plan/transaction/target/guard/operation set across all; `guard_digest` = plan H0 = S0 guard; `s1_guard_digest` = S1 guard; `journal_head_sha256` equals the chain head; `verification_result_sha256 == digest(verification, vidtoolz.resolveVerificationResult.v1)`; verdict `VERIFIED`; last journal state `PUBLISHED|COMMITTED|COMMITTED_RECOVERED`; terminal state allowed; no unresolved conflict; evidence digests present; `authority_version` = active.
- **Linked set** (`validate_transaction_set({s0_snapshot, plan, journal, s1_snapshot, verification, commit, conflicts}, perms, rp, caps, tc, evidence_set, active, schema_validate, callable_methods)`): the authority for cross-artifact consistency, in this order: schema every member (a schema failure stops the set) → **S0** validation (complete `WRITE_PRECHECK`) → **plan** validation against S0's guard → **journal** validation with the plan (membership) → **S1** validation and lineage → **derived delta** → **expected effect** → **verification vs derived truth** → **commit eligibility**; a journal that reached `COMMITTED` without a commit manifest fails. There is no commit-by-hash shortcut.
