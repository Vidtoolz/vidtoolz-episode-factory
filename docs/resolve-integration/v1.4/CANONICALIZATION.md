# Canonicalization specification v1.4 (FROZEN_NOW; Node conformance = M1 work)

Reference: `tools/authority_lib.py`; vectors `fixtures/canonicalization/vectors.json`; rejections `fixtures/canonicalization/rejections.json`.

1. **Encoding/objects/strings/integers/booleans**: UTF-8, no whitespace, keys sorted by code point, exact strings with the fixed escape set, integers within ±(2^53−1). Bare floats, NaN, Infinity, lone surrogates rejected. No Unicode normalization: byte-distinct strings stay distinct.
2. **Tagged numerics (validated, not accepted as arbitrary strings)**: `{"$rational":"p/q"}` MUST match `^(0|[1-9][0-9]*)/([1-9][0-9]*)$` and be reduced (so `2/4`, `1/0`, `-1/2`, leading zero and whitespace are rejected). `{"$f64":"<16 lowercase hex>"}` is IEEE-754 binary64 big-endian matched with **full-string semantics** (`re.fullmatch`): any leading/trailing whitespace, newline, tab or CR, uppercase or mixed case, short, long, non-hex, `0x` prefix, non-ASCII digits, empty or non-string values are rejected; one bit pattern has exactly one text; NaN/Infinity (exponent all ones) and negative zero (`8000000000000000`, must be `0000000000000000`) are rejected.
3. **Nullable fields** are emitted as `null`, never omitted. v1.4: every timeline/project/track/item observable field is nullable with a status (`SNAPSHOT-COMPLETENESS.md`); a timeline with every field `UNAVAILABLE` is representable and hashable (vector `unobserved_timeline_all_null_with_status`).
4. **Typed array ordering** (applied by `normalize_snapshot_payload`): tracks by (type order video<audio<subtitle, integer index; string index and duplicate address rejected); items by the **status-aware key** ((start-status rank, start), (end-status rank, end), kind order, unique_id, `observation_ordinal`) — `OBSERVED` frames sort by value, unavailable frames by status rank, so a partially observed item needs no invented value (option A); exact-tuple collision and duplicate ordinal rejected; `observation_failures` ledger sorted by (track_address, ordinal, reason); **markers by the total key (object_address, frame, duration, custom_data, name, color, note)**, and two markers sharing (object_address, frame) or exactly duplicated are rejected as `MARKER_COLLISION`; media dependencies by (locator, sha) with duplicates rejected. Ordering never relies on input order (vectors: reversed marker input and reversed track/item input give the same digest; the validator additionally permutes every snapshot fixture under a seeded RNG).
5. **Duplicate JSON keys (policy A)**: canonicalization operates on parsed objects and cannot see source duplicates. Authority files MUST be loaded through `strict_loads`/`strict_load`, which reject duplicate keys at the parse boundary (`fixtures/parse/duplicate-key.json.txt`). The dictionary-level duplicate check in `canon` is a programming guard, not a source-duplicate detector.
6. **Domain-tagged digests**: `sha256(utf8(domain) + 0x0A + canonical_bytes)`; registered domains only: `vidtoolz.resolveSnapshotPayload.v1.4`, `vidtoolz.resolveGuard.v2`, `vidtoolz.resolveSnapshotObject.v1` (whole snapshot with normalized payload — the readback identity), `vidtoolz.resolveMutationPlan.v1`, `vidtoolz.resolveOperationSet.v1`, `vidtoolz.resolveBindingSet.v1`, `vidtoolz.resolveJournalRecord.v1`, `vidtoolz.resolveEvidenceRecord.v1`, `vidtoolz.resolveVerificationResult.v1`, `vidtoolz.resolveGeneric.v1`. The v1.3 payload domain and the v1 guard domain are unregistered (rejection `unregistered_domain_old_guard_v1`).
7. **Evidence record ids**: `record_id = digest(body without record_id, vidtoolz.resolveEvidenceRecord.v1)`; the envelope is part of the body, so a record cannot be re-bound to another manifest, host, session or sequence without changing its identity (`validate_evidence_set` re-hashes every record).
