# SEMANTIC-VALIDATION.md — schema validity is not authorization (v1.7, FROZEN_NOW as doctrine; validators NOT runtime-qualified)

**SCHEMA-VALID != AUTHORIZED TO MUTATE.** JSON Schema proves shape. Authority requires the layers below, implemented as a reference in `tools/authority_lib.py` and exercised by `tools/validate_v1_6.py`. Nothing has run against Resolve.

## Authority surface (v1.6)

`authority_lib.AUTHORITY_SURFACE` is the closed list of functions that may decide anything:
- **authorizing**: `commit_eligibility_authorizing` (the ONLY commit entry point), `validate_transaction_set_authorizing` (the composed transaction validator it wraps), `evaluate_eligibility_authorizing`, `derive_attachment_state_authorizing` (and their `*_for_session` forms), `load_governed_evidence_set`, `governed_consume`, `primitive_status`, `callable_method_set`, `promotion_state`;
- **diagnostic, non-authorizing** (v1.14 V113-B1): the DIAGNOSTIC / NON_AUTHORIZING `derive_attachment_state` and the DIAGNOSTIC / NON_AUTHORIZING `evaluate_eligibility` — the same semantic derivations over a bare evidence set, with no governed provenance and no location receipt;
- **provisional until M3, non-authorizing** (v1.15 V114-B2): the PROVISIONAL_UNTIL_M3 non-authorizing `commit_eligibility` and the PROVISIONAL_UNTIL_M3 non-authorizing `validate_transaction_set` — the same composed validation over a bare evidence set. Every stage law is identical; without governed provenance the result is not write authority;
- **INTERNAL_NON_AUTHORIZING** (composed by the above; documented as such in every docstring; never an authorization surface): `semantic_mutation_plan`, `semantic_journal`, `semantic_verification_result`, `semantic_conflict`, `semantic_commit_manifest`, `semantic_snapshot`, `verify_transaction`, `derive_delta`, `occurrence_index`, `expected_effects`, `guard_lineage_errors`, `journal_readback`, `profile_satisfies`, `required_s1_profile`, `capability_qualification`, `derive_capability_result`, `semantic_raw_capture`, `semantic_review_decision`, `semantic_refreeze_record`, `semantic_derived_result_record`, `semantic_identity_observation`, `identity_claims`, `guard_record_errors`, `active_authority_errors`, `capability_matrix_digest`, `primitive_spec_digest`, `primitive_spec`, `codec_errors`, `codec_broad_type`, `codec_contains_elision`, `raw_capture_digest`, `raw_capture_digest_ok`, `promotion_step`, `classification_family`.

The earlier direct helpers survive only as these internal functions. `semantic_commit_manifest` and `semantic_verification_result` require plan, S0, S1, journal (and the active authority) as objects and return an error for any missing input — there is no hash-only path and no default that lets a caller omit S0 or S1.

**v1.6: schema enforcement is not optional.** `schema_validate` was then a **required positional parameter** of the composed validators (v1.7 removed it entirely — the authority resolves schemas internally, and passing anything in its place is refused by name; see `SCHEMA-REGISTRY.md`). A call without it refuses (`schema: a schema validator is REQUIRED`) instead of completing the schema stage without validating, so an unsupported or invented field in any linked artifact cannot pass through a default (Codex F15-04). `validate_transaction_set_authorizing` still has no callable-set, skip or override parameter, derives the capability/provenance context itself, and first requires that the supplied capability matrix **is** the active matrix by content digest (`CAPABILITY_MATRIX_NOT_ACTIVE`, Codex F15-02). The validator's `bypass-audit` section checks the surface list, the docstrings, the signatures, the **defaults** and the behaviour of every exported validator.

## Layers (every fixture records its expected failure layer)

`raw parse` → `schema` → `evidence-binding` (envelope, active manifest, record laws) → `attachment` → `capability` (raw capture → reference parser → review → refreeze → content-bound active matrix) → `snapshot` (observation model, field provenance, occurrence uniqueness) → `semantic` (binding, membership, readback→S1, derived verification) → `eligibility` → `linked-set` / composed authorization. A positive fixture must pass every layer; a negative must fail at exactly the declared layer with the declared error substring. A check that raises is a **FAIL**. Seeded random permutations of evidence maps, request keys, snapshot arrays (tracks/items/markers/ledger), conflicts and linked-set key order must give identical results; duplicate-identity inputs must reject identically. The Codex v1.5 findings F15-01…F15-07, the independent architectural findings M-RAW / M-H0 / M-PRECEDENCE / M-ID and their combinations are pinned in `v1.5-attack`.

Bound across plan, journal (every record), S0, S1, verification and commit — no partial combination is accepted: **`authority_version`** (`1.7.0`), **`plan_digest`** (= `digest(plan without plan_digest/refs, vidtoolz.resolveMutationPlan.v1)`), **`transaction_id`**, **target** (`target` / `target_ref` / S0-S1 library+project+timeline identity + `target_epoch`), **H0/S0 guard** (`h0_guard_digest` = S0 `guard_digest` = journal `guard_digest` = commit `guard_digest`), **`operation_set_digest`** (plan, every journal record, commit; `expected_delta_digest` in verification), **execution/readback session** (`plan.session_id` = every journal record `session_id` = `S0.collection.session_id` = `S1.collection.session_id` = `verification.session_id` = `commit.session_id` = `evidence_set.current_session_id`), **S1 digest** (journal `READBACK_S1.readback_snapshot_sha256` = `verification.readback_snapshot_sha256` = `commit.s1_snapshot_sha256` = `snapshot_object_digest(S1)`; `readback_guard_digest` = `s1_guard_digest` = S1 `guard_digest`), **verification digest** (`commit.verification_result_sha256` = `digest(verification, vidtoolz.resolveVerificationResult.v1)` of the object that passed).

## Per-document rules

- **Plan** (`semantic_mutation_plan`): `plan_digest` and `operation_set_digest` recompute; unique operation ids; `session_id` present and equal to the evidence set's current session; permission class × ops; selector completeness and target match; `APPEND` requires `expected_new {start, end}`; guard presence; `STALE_SNAPSHOT` if the current guard differs; dry-run law; every operation eligible under the active authority.
- **Journal** (`semantic_journal(records, plan, s1)`): non-empty; single `transaction_id`, `plan_digest`, `operation_set_digest`, `session_id` (== plan), constant `target_ref`; constant `guard_digest` except across `RECOVERY_RECONCILING`; contiguous sequence; hash chain; execution law `PREPARED → LEASED → PREFLIGHT_OK → CHECKPOINTED → OP_STARTED → APPLIED | OP_FAILED → READBACK_S1 → VERIFIED → SAVED → PUBLISHED → COMMITTED` (+ failure/recovery branches). **v1.6: `CHECKPOINTED` is mandatory** — `PREFLIGHT_OK` may not go directly to `OP_STARTED`, and the `CHECKPOINTED` record must carry `checkpoint {checkpoint_sha256, …}` evidence (DuplicateTimeline + DRT export + SaveProject); only that record may carry a checkpoint (Codex F15-07); operation membership (op id + type from the bound plan; started/applied at most once; APPLIED after its own OP_STARTED; READBACK_S1 after every plan op APPLIED); **readback binding**: at most one `READBACK_S1`, carrying `readback_snapshot_sha256` and `readback_guard_digest`; only that record may carry them; when S1 is supplied they must equal `snapshot_object_digest(S1)` and S1's guard, S1 must be from the journal's session, and a supplied S1 without a readback event is an error.
- **S0 / S1** (`semantic_snapshot(snap, ctx)`, `guard_lineage_errors`): schema + semantic validity under the active authority context (callable set derived; every OBSERVED field/domain backed by cited qualifying provenance; unique occurrence identity); S0 is a complete `WRITE_PRECHECK` snapshot whose guard is the plan's H0 and whose identity equals the plan target; S1 shares library, project, timeline identity, `target_epoch` **and session** with S0 and the plan; S1 satisfies the operation's verify profile (`required_s1_profile`, `profile_satisfies`) and is complete.
- **Protected surface and derived delta** (`derive_delta`): occurrence index by OBSERVED `unique_id` (duplicates → `DUPLICATE_OCCURRENCE_IDENTITY`, not derivable); per occurrence `PROTECTED_ITEM_FIELDS` = track type/index, start, end, duration, enabled, media pool item id, media id, source start/end, source sha/locator/status, name, provenance kind, item markers; `PROTECTED_TIMELINE_FIELDS` = unique_id, name, start_frame, end_frame, start_timecode, fps, width, height, settings (`is_current` and `duration_convention` are explicitly unprotected — adapter selection state and a constant); `PROTECTED_TRACK_FIELDS` = name, enabled, locked plus track topology (tracks added/removed); timeline markers added/removed; media dependencies added/removed. **Explicit exclusions (`PROTECTED_SURFACE_EXCLUSIONS`, v1.6): item properties (transform/crop/composite/audio), fades, speed, takes, linked items and unowned media hashes are NOT observed, NOT represented in the snapshot schema and NOT compared.** They may only appear as deferred or unobservable domains — observing them is a snapshot error — and every verification result lists them in `unobserved_domains`, so the guarantee is narrower and honest rather than claimed and unrepresentable. Result: `added`, `removed`, `changed`, `markers_added/removed`, `timeline_changed`, `tracks_added/removed/changed`, `media_added/removed`.
- **Unrelated-change law** (`verify_transaction`): every protected change not explained by an APPLIED plan operation's expected effect is `unrelated`; `unrelated` and `missing_expected` are derived, never declared; a caller's `unrelated: []` is compared against the derived truth and rejected when it differs. Explained by APPEND: the new occurrence matching track/range/media identity (creation identity mapped), a media dependency for that occurrence's source, and `timeline.end_frame` growing exactly to the new occurrence end (or end+1 under the unqualified convention). Verdicts: `VERIFIED` | `EXPECTED_DELTA_MISSING` | `UNEXPECTED_DELTA` | `UNOBSERVABLE_STATE` (incomplete S0/S1, unobserved or duplicate identity) | `EFFECT_NOT_SPECIFIED`.
- **Expected effects** (`expected_effects`, provisional): APPEND → added item on selector track at `expected_new` with expected media identity; DELETE → removed; DISABLE/ENABLE → enabled flip only; UPSERT_MARKER → marker present by `custom_data`; every other op → NOT_YET_SPECIFIED (never VERIFIED).
- **Verification** (`semantic_verification_result(vr, plan, s0, s1, journal)` — all mandatory): declared `added/removed/changed/creation_identity_map/missing_expected/unrelated/applied_operation_ids/unobserved_domains/verdict` equal the derived truth (**v1.6: `applied_operation_ids` is compared, so a ghost id for an operation that was never applied is rejected — Codex F15-06; and `unobserved_domains` names the excluded and deferred domains in every result, so no zero-unintended-change claim can be read as covering them — Codex F15-05**); `VERIFIED` requires every effect matched, every op APPLIED, no unrelated change, effects specified; `h0_*` digests resolve to S0 and `s1_*` + `readback_snapshot_sha256` to S1; readback digest equals the journal's single `READBACK_S1`; bound to plan/transaction/target/guard/expected-delta/session; never human approval.
- **Conflict** (`semantic_conflict`): `authority_effect NONE_UNTIL_HUMAN_ADJUDICATION`; bound to plan/transaction; `resolved` is a human flag.
- **Commit manifest** (`semantic_commit_manifest(cm, plan, journal, verification, conflicts, s0, s1, active)` — all mandatory): re-validates journal (with S1) and verification (against derived truth); same plan/transaction/target/guard/operation set/session; `s1_guard_digest` and `s1_snapshot_sha256` = S1; `journal_head_sha256` = chain head; `verification_result_sha256` = digest of the validated object; verdict VERIFIED; terminal state allowed; no unresolved conflict; evidence digests; authority version.

## Single authority: `commit_eligibility_authorizing` → `validate_transaction_set_authorizing`

`validate_transaction_set_authorizing({s0_snapshot, plan, journal, s1_snapshot, verification, commit, conflicts}, perms, rp, caps, tc, GovernedEvidenceSet, active)` executes `VALIDATION_STAGES` in order and cannot skip any: **evidence_authority** (`validate_evidence_set` against the active manifest) → **capability_provenance** (context from the active matrix + evidence set) → **schema** (every member) → **s0** (semantic + provenance + complete `WRITE_PRECHECK`) → **plan** (against S0's guard, eligibility under the active authority) → **journal** (membership, session, readback binding to S1) → **s1** (semantic + provenance, lineage incl. session, required verify profile, completeness) → **delta** (identity errors) → **effects** (`verify_transaction`; a non-VERIFIED derived verdict with a commit present is an error) → **verification** (declared vs derived) → **conflicts** → **commit** (INELIGIBLE without linked S1 and verification). `commit_eligibility_authorizing` requires a `GovernedEvidenceSet` plus S0, plan, journal, S1, verification and commit objects and returns `{eligible, errors, stages_completed}`; it is eligible only with zero errors and every stage completed. A verification object, a hash or a receipt is never sufficient on its own; missing linked S0/S1 → INELIGIBLE; a false VERIFIED object → INELIGIBLE.
