# Canonicalization specification v1.3 (FROZEN_NOW; Node conformance = M1 work)

Reference: `tools/authority_lib.py`; vectors `fixtures/canonicalization/vectors.json`; rejections `fixtures/canonicalization/rejections.json`.

1. **Encoding/objects/strings/integers/booleans**: UTF-8, no whitespace, keys sorted by code point, exact strings with the fixed escape set, integers within ±(2^53−1). Bare floats, NaN, Infinity, lone surrogates rejected. No Unicode normalization: byte-distinct strings stay distinct (vector `unicode_byte_distinct_strings`).
2. **Tagged numerics (validated, not accepted as arbitrary strings)**: `{"$rational":"p/q"}` MUST match `^(0|[1-9][0-9]*)/([1-9][0-9]*)$` and be reduced (so `2/4`, `1/0`, `-1/2` are rejected). `{"$f64":"<16 lowercase hex>"}` is IEEE-754 binary64 big-endian and is matched with **full-string semantics** (`re.fullmatch`, v1.3): any leading/trailing whitespace, newline, tab or CR, uppercase or mixed case, short, long, non-hex, `0x` prefix, non-ASCII digits, empty or non-string values are rejected; one bit pattern has exactly one text (negative zero rejected, so `+0.0` is the only zero); NaN/Infinity (exponent all ones) and negative zero (`8000000000000000`, must be `0000000000000000`) are rejected.
3. **Nullable fields** are emitted as `null`, never omitted.
4. **Typed array ordering** (applied by `normalize_snapshot_payload`): tracks by (type order video<audio<subtitle, integer index; string index and duplicate address rejected); items by the **status-aware key** ((start-status rank, start), (end-status rank, end), kind order, unique_id, `observation_ordinal`) — `OBSERVED` frames sort by value, unavailable frames by status rank, so a partially observed item needs no invented value (option A, `SNAPSHOT-COMPLETENESS.md`); exact-tuple collision and duplicate ordinal rejected; `observation_failures` ledger sorted by (track_address, ordinal, reason); **markers by the total key (object_address, frame, duration, custom_data, name, color, note)**, and two markers sharing (object_address, frame) or exactly duplicated are rejected as `MARKER_COLLISION`; media dependencies by (locator, sha) with duplicates rejected. Ordering never relies on input order (vectors: reversed marker input gives the same digest; markers differing only in note or duration order deterministically).
5. **Duplicate JSON keys (policy A)**: canonicalization operates on parsed objects and cannot see source duplicates. Authority files MUST be loaded through `strict_loads`/`strict_load`, which reject duplicate keys at the parse boundary (`fixtures/parse/duplicate-key.json.txt`). The dictionary-level duplicate check in `canon` is a programming guard, not a source-duplicate detector.
6. **Domain-tagged digests**: `sha256(utf8(domain) + 0x0A + canonical_bytes)`; registered domains only (`vidtoolz.resolveSnapshotPayload.v1.3`, `vidtoolz.resolveGuard.v1`, `vidtoolz.resolveMutationPlan.v1`, `vidtoolz.resolveOperationSet.v1`, `vidtoolz.resolveBindingSet.v1`, `vidtoolz.resolveJournalRecord.v1`, `vidtoolz.resolveEvidenceRecord.v1`, `vidtoolz.resolveVerificationResult.v1`, `vidtoolz.resolveGeneric.v1`).
7. `canonicalization_version` is `"1.3"`. Vectors: `fixtures/canonicalization/vectors.json` (19); rejections: `fixtures/canonicalization/rejections.json` (36, incl. 16 `$f64` syntax cases, 5 `$f64` NaN/Infinity/negative-zero cases and 6 `$rational` cases).
