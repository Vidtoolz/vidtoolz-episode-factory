# SEMANTIC-VALIDATION.md — schema validity is not authorization (v1.3, FROZEN_NOW as doctrine; validators NOT runtime-qualified)

**SCHEMA-VALID != AUTHORIZED TO MUTATE.** JSON Schema proves shape. Authority requires the layers below, implemented as a reference in `tools/authority_lib.py` and exercised by `tools/validate_v1_3.py`. Nothing has run against Resolve.

## Layers (every fixture records its expected failure layer)

`raw parse` (strict duplicate-key rejection, `strict_loads`) → `schema` (Draft 2020-12) → `semantic` (reference rules per document) → `eligibility` (`evaluate_eligibility` over frozen authorities + evidence set) → `linked-set` (`validate_transaction_set`). `layer_expected_failure ∈ {none, parse, schema, semantic, eligibility, linked-set}`. A positive fixture must pass every layer; a negative must fail at exactly the declared layer with the declared error substring. A check that raises an exception is recorded as **FAIL** (never "passes because an exception happened").

## Cross-artifact binding model (v1.3)

Binding tuple shared by mutation plan, transaction journal, verification result, conflict record and commit manifest: **`plan_digest`** (= `digest(plan without plan_digest/refs, vidtoolz.resolveMutationPlan.v1)`), **`transaction_id`**, **target identity** (`target` object in plan/verification/commit; `target_ref` = library UUID + project id + timeline id in every journal record), **guard** (`h0_guard_digest` in plan/verification; `guard_digest` in journal records and commit), **operation set** (`operation_set_digest` = `digest(operations, vidtoolz.resolveOperationSet.v1)` in plan and commit; `expected_delta_digest` in verification), **`authority_version`** (`1.3.0`, const in the provisional schemas).

- **Plan** (`semantic_mutation_plan`): `plan_digest` recomputes; `operation_set_digest` recomputes; permission class × ops; selector completeness and target match; guard presence for guard-required ops; `STALE_SNAPSHOT` if the current guard differs; dry-run law; payload-as-guard rejected; every operation eligible via `evaluate_eligibility` with the plan's `refs` (non-dry-run).
- **Journal** (`semantic_journal(records, plan)`): non-empty; single `transaction_id`, single `plan_digest`, constant `target_ref`; constant `guard_digest` except across a `RECOVERY_RECONCILING` record; contiguous sequence from 0; hash chain over `vidtoolz.resolveJournalRecord.v1`; transitions per `JOURNAL_TRANSITIONS`; unique `operation_id` per `APPLIED`; `RECOVERY_RECONCILING.recovery_of_transaction_id == transaction_id`; nothing after a terminal state; when a plan is given, every binding field equals the plan's.
- **Verification** (`semantic_verification_result(vr, plan)`): `VERIFIED` forbids `unrelated`/`missing_expected`; `is_human_approval` false; `plan_digest`, `transaction_id`, `target`, `h0_guard_digest` equal the plan; `expected_delta_digest == plan.operation_set_digest`; `s1_guard_digest`/`readback_snapshot_sha256` identify the actual readback.
- **Conflict** (`semantic_conflict(cf, plan)`): `authority_effect NONE_UNTIL_HUMAN_ADJUDICATION`; bound to `plan_digest`/`transaction_id`; `resolved` is a human flag.
- **Commit** (`semantic_commit_manifest(cm, plan, journal, verification, conflicts, guard)`): **composes** validation — journal and verification objects are re-validated here (a hash-only caller is refused: "commit requires plan, journal and verification objects"); same plan/transaction/target/guard across all; `journal_head_sha256` equals the chain head; `verification_result_sha256 == digest(verification, vidtoolz.resolveVerificationResult.v1)`; verdict `VERIFIED`; last journal state `PUBLISHED|COMMITTED|COMMITTED_RECOVERED`; terminal state allowed; no unresolved conflict (listed or as a record with `resolved: false`); evidence digests present; `authority_version 1.3.0`.
- **Linked set** (`validate_transaction_set({plan, journal, verification, commit, conflicts, guard_snapshot_digest}, perms, rp, caps, tc, evidence_set, schema_validate)`): the authority for cross-artifact consistency. Schema-validates every member first (a schema failure stops the set), then runs every semantic check above with the plan as the binding anchor, then requires a commit manifest whenever the journal reached `COMMITTED`. Individual-document validation remains necessary but insufficient.
